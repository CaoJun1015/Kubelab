# KubeLab M8 产品需求文档——实验作者工具链

> 文档版本：v1.0  
> 文档状态：已批准实施
> 建议开发版本：`0.5.0a0`  
> 前置条件：M7完成并形成稳定的路径与内容契约  
> 主要入口：WSL2 Ubuntu中的KubeLab CLI

---

## 1. 产品定义

M8为KubeLab实验作者提供一套本地、确定性、安全优先的实验创建与验收工具链，使贡献者能够从模板生成实验，通过静态规则和Fake Gateway证明实验契约，检查公开内容泄漏，并构建可复现的实验包。

M8服务的是“实验内容生产”，不是学习者的浏览器操作。运行时仍以现有Lab/Variant Schema、Registry、Application Service和验证器为唯一真源，作者工具不得复制一套兼容性逐渐漂移的解析器。

## 2. 背景与问题

当前新增实验需要作者手工创建多个YAML、Manifest、README和标准修复文件，并理解大量隐含约束：

1. 文件结构、ID、Namespace、资源类型和镜像策略容易写错。
2. “初始契约通过、成功契约失败、修复后通过、reset恢复”需要手工编写测试。
3. LabVariant继承、目录归属和摘要校验规则不容易被新贡献者掌握。
4. 双根因实验需要证明第一处修复后第二处故障仍然可观察。
5. 内容可能意外泄漏Secret、内部验证值、完整Manifest或标准答案。
6. 本地能运行的内容不一定被正确打包进wheel/sdist。
7. 直接使用真实minikube验收成本高，并存在误操作非本地集群的风险。

## 3. 产品目标

### 3.1 核心目标

1. 作者在10分钟内生成一个结构正确、默认安全的实验骨架。
2. 在不访问真实集群的情况下，发现大多数Schema、内容、安全和生命周期错误。
3. 用统一命令证明普通实验、变体和双根因实验的关键契约。
4. 在提交代码前检查学习者可见内容是否泄漏答案或敏感信息。
5. 生成内容确定、摘要可验证、与本机路径无关的实验包。
6. 可选真实验收只允许显式信任的本机minikube，并在结束后完成残留审计。

### 3.2 成功标准

- 新实验无需修改核心代码即可完成脚手架、校验、Fake测试和打包。
- 无效实验在Registry加载之前即可获得定位到文件和字段的错误。
- 同一输入在不同机器构建出内容一致的包。
- 工具默认不覆盖现有文件、不执行任意Shell、不连接远程集群。
- 作者测试使用与运行时相同的Schema、安全策略和验证器契约。

## 4. 非目标

M8不实现：

- Web实验编辑器或浏览器YAML编辑器；
- 用户提供任意Shell、Python或可执行验证插件；
- 自动生成故障根因或标准答案；
- 自动修改作者Manifest以“修好”规则错误；
- 第三方实验市场、远程仓库安装或自动发布；
- 包签名、信任联盟或供应链市场治理；
- Helm Chart、Operator或任意CRD测试框架；
- 远程集群、生产集群或多集群验收；
- 为作者工具复制第二套Lab Schema或Registry；
- 绕过现有Context Trust、readiness和Namespace安全边界。

## 5. 目标用户

### 5.1 核心维护者

需要批量扩展内置实验、维护验证器契约并保证发布产物完整。

### 5.2 开源贡献者

熟悉基础Kubernetes，但不熟悉KubeLab内部代码，希望通过模板和清晰错误完成首个实验贡献。

### 5.3 内容审核者

需要在代码评审时快速判断实验是否可复现、是否只修改故障字段、是否泄漏答案以及是否具备清理能力。

## 6. 产品原则

1. **运行时规则唯一。** 作者工具直接复用现有Schema、Registry、安全检查和验证定义。
2. **静态优先，真实集群可选。** 默认所有命令不访问Kubernetes；集成验收必须显式开启。
3. **生成安全默认值。** 脚手架从固定模板生成受限资源、固定镜像和最小权限内容。
4. **验证契约，不猜作者意图。** 工具报告错误和证据，但不自动重写业务内容。
5. **失败关闭。** 未知字段、危险资源、摘要不一致或不可信Context必须终止。
6. **产物可复现。** 包不得携带数据库、日志、凭证、kubeconfig、本机绝对路径或构建时间噪声。

## 7. 命令范围

M8新增统一命令组：

```text
kubelab lab init
kubelab lab lint
kubelab lab test
kubelab lab inspect
kubelab lab package
```

所有命令面向本地文件系统。除显式集成测试外，不启动实验Session，不写用户学习数据库，不操作Kubernetes资源。

## 8. 核心用户流程

### 8.1 创建普通实验

```text
lab init选择baseline模板
→ 编辑lab.yaml、README、故障Manifest和标准修复
→ lab lint
→ lab test使用Fake Gateway验证生命周期
→ lab inspect检查公开内容与修复差异
→ lab package生成候选包
```

### 8.2 创建固定变体

```text
在父实验目录执行lab init --type variant
→ 自动生成variant-b或variant-c目录
→ 继承父实验安全边界与requirements
→ lint验证归属、顺序、摘要和揭示内容
→ test证明盲练与修复契约
```

### 8.3 创建双根因实验

```text
lab init选择composite模板
→ 定义两个有序根因和分阶段证据
→ test先验证初始状态
→ 应用第一阶段修复，确认第二根因仍可观察且最终契约未通过
→ 应用完整修复，确认成功契约通过
→ reset确认恢复两个根因
```

### 8.4 可选本机集成验收

```text
作者显式启用integration
→ 检查WSL2 Ubuntu、readiness和Context Trust
→ 在唯一临时Namespace运行契约
→ cleanup并执行残留审计
→ 输出脱敏JUnit和摘要
```

工具不得自动信任Context，不得在失败后删除归属不明确的资源。

## 9. 功能需求

### FR-M8-001 实验脚手架

`kubelab lab init`必须：

- 支持`baseline`、`variant`和`composite`三类模板；
- 生成严格的目录结构、Schema版本、README、故障Manifest、标准修复和契约测试骨架；
- 为ID、标题、分类和难度提供显式参数或交互式输入；
- 默认使用允许的Kubernetes资源类型、资源限制和固定镜像示例；
- 普通/综合实验生成恰好三层提示和三个复盘问题占位；
- 变体生成通过后公开的证据、根因、修复和预防字段；
- 目标目录非空或目标文件已存在时失败，不默认覆盖；
- 支持`--dry-run`预览文件清单，不写入磁盘。

首版不提供批量重命名或移动实验能力。

### FR-M8-002 静态校验

`kubelab lab lint`复用运行时规则并检查：

#### Schema与文件结构

- API版本、kind、必填字段和未知字段；
- 实验ID、变体ID、目录名和父实验归属；
- 重复ID、重复顺序、越界路径和缺失文件；
- Manifest摘要和注册后篡改；
- README、标准修复和教学材料存在。

#### Kubernetes安全

- Namespace归属和固定前缀；
- 允许的资源类型及危险字段；
- 禁止Secret内容、hostPath、hostNetwork、privileged、hostPID、hostIPC和越权RBAC；
- 容器资源requests/limits；
- 固定镜像标签，不允许`latest`；
- Workspace权限没有扩大。

#### 教学契约

- 恰好三层提示，第二层命令适用于受限Workspace；
- 恰好三个静态复盘问题；
- 初始检查、成功检查和reset材料完整；
- 变体通过前内容不包含场景名称、根因或标准修复；
- 综合实验定义两个可区分的根因阶段；
- 公开消息不含expected/actual、堆栈、完整Manifest或凭证。

#### 修复差异

- 标准修复只修改声明的故障字段；
- 不可变资源明确使用安全删除再重建步骤；
- 删除目标必须限定在实验Namespace和归属资源；
- reset能够恢复初始故障内容。

### FR-M8-003 Fake契约测试

`kubelab lab test`默认使用Fake Gateway，普通实验必须证明：

```text
初始检查通过
→ 成功检查在修复前失败
→ 应用标准修复后成功检查通过
→ reset后初始检查重新通过且成功检查失败
```

变体还必须证明：

- 父实验继承项正确；
- 未通过时公共DTO不泄漏变体身份和答案；
- 通过后揭示正确场景信息；
- reset和恢复保持原变体。

综合实验还必须证明：

- 第一根因修复前第二阶段不是错误地判定为完成；
- 第一根因修复后第二根因仍可观察；
- 只有两个根因全部修复才通过；
- reset恢复两个故障。

### FR-M8-004 结构检查与预览

`kubelab lab inspect`提供面向审核者的只读报告：

- 解析后的实验族、场景类型和继承来源；
- 资源类型、名称、镜像和权限摘要；
- initial/success checks的公开结构摘要；
- 故障Manifest与标准修复之间的允许字段差异；
- 学习者在通过前和通过后分别可见的内容；
- 文件摘要、包内容清单和潜在泄漏告警。

报告不得输出Secret值、原始异常、完整kubeconfig或未脱敏的环境变量。

### FR-M8-005 公开边界审计

工具必须模拟Registry、Application Service和Web DTO的公开输出，并检测：

- Secret、token、password、Authorization和私钥模式；
- Kubernetes完整Manifest或大段YAML；
- 验证器expected/actual内部值；
- Python堆栈、异常正文和本机绝对路径；
- 未通过变体的内部ID、名称、根因和修复；
- 未转义HTML和可执行脚本内容。

命中高风险规则时`lint`和`package`失败；低风险内容给出稳定警告码。

### FR-M8-006 确定性打包

`kubelab lab package`必须：

- 仅打包指定实验族及其合法变体；
- 在打包前强制执行lint和Fake契约测试；
- 生成机器可读索引、Schema版本和每个文件的SHA-256摘要；
- 固定归档顺序、权限和时间戳，使同一输入产生一致内容；
- 输出建议格式`.kubelab-lab.tar.gz`；
- 验证归档内路径不能逃逸包根目录；
- 不包含Git元数据、数据库、日志、缓存、JUnit、kubeconfig、Token或本机绝对路径；
- 构建完成后重新读取并校验摘要。

生成包不代表安装。M8不提供第三方包自动导入运行时的能力。

### FR-M8-007 错误模型

所有作者命令输出统一错误结构：

- 稳定错误码；
- 严重级别；
- 相对文件路径；
- 字段路径或资源定位；
- 脱敏的人类可读说明；
- 固定文档链接或修复方向。

错误不得包含Secret值、整份Manifest、堆栈或用户目录。CLI支持人类可读和JSON两种格式，并保持一致的退出码约定。

### FR-M8-008 可选真实集成测试

`kubelab lab test --integration`必须：

- 默认关闭，并要求现有真实集成变量显式启用；
- 仅允许WSL2 Ubuntu内本机Docker驱动的`minikube` profile；
- 要求Context已被KubeLab信任，身份漂移时失败关闭；
- 执行实验级readiness和requirements检查；
- 使用唯一、受归属保护的Namespace；
- 复用正式Application Service、Gateway和验证器，不走专用捷径；
- 生成脱敏JUnit结果和生命周期摘要；
- 完成后检查Namespace、Workspace RBAC、Probe Pod、PVC/PV和临时文件残留；
- 失败时保留安全证据，但不自动清理归属不明确的残留。

不得自动启动远程集群、自动信任Context或修改用户正式数据库。

### FR-M8-009 文档生成

脚手架和inspect输出应帮助作者完成：

- “是什么、为什么、怎么做”的实验教材；
- 现象、成功目标和证据清单；
- 三层提示；
- 根因、最小修复和预防措施；
- 标准复盘问题；
- 本地Fake测试和可选集成验收说明。

模板提供结构和示例语气，但不自动生成答案内容。

## 10. CLI交互约定

### 10.1 输入

- 路径必须解析到当前工作区内，拒绝`..`逃逸和符号链接越界。
- ID必须符合现有Lab/Variant格式，不从标题自动猜测最终ID。
- 非交互CI中缺少必填参数应立即失败。
- 任何需要覆盖文件的行为首版均不提供隐式确认；作者应自行处理冲突文件。

### 10.2 输出与退出码

- `0`：全部通过；
- `2`：作者输入或Schema错误；
- `3`：安全策略或公开边界失败；
- `4`：契约测试失败；
- `5`：环境或可选集成前置条件不满足；
- `10`：已脱敏的内部工具错误。

JSON输出必须包含命令、结果、错误列表和计数，不包含绝对用户路径。

## 11. 架构边界

- CLI与Web继续共享现有Application Service，但作者命令可调用专门的Authoring Service。
- Authoring Service必须组合现有Lab Schema、Registry、安全校验器和验证定义，不得复制实现。
- 默认Fake测试不创建正式Session，也不写学习进度数据库。
- 真实集成测试通过现有生命周期服务执行，并使用隔离的临时数据目录。
- 作者工具不得直接调用Web、启动Web子进程或通过Web调用CLI。
- 打包器只读取已校验文件，不执行包内任何内容。

## 12. 数据与API影响

- M8不新增Web API或页面。
- M8不新增学习数据库表或迁移。
- 作者测试结果默认输出到用户指定目录，不进入Session时间线或进度统计。
- 实验包索引是构建产物元数据，不是新的运行时业务状态。
- 如果未来支持第三方包安装，应另立PRD处理签名、信任、升级和卸载，不能在M8中隐式加入。

## 13. 安全要求

1. 默认命令不访问网络、不访问Kubernetes、不执行Shell。
2. YAML字段不得承载任意命令、脚本路径、Python模块或动态插件。
3. Manifest解析必须限制文件大小、文档数量、递归深度和资源数量。
4. 归档必须防止路径穿越、符号链接逃逸和压缩炸弹。
5. 日志、JSON、JUnit和错误消息必须统一脱敏。
6. 集成测试只允许精确匹配并已信任的本机minikube身份。
7. 清理必须校验Namespace前缀、归属标签和Session/测试运行标识。
8. 生成文件使用原子写入；目标存在时不得静默覆盖。
9. 包内不得包含Secret资源，即使Secret值为空或看似测试数据。

## 14. 测试与验收

### 14.1 脚手架

- 三种模板均能生成完整、可lint的目录。
- 非空目录、重复ID、非法路径和符号链接越界均失败。
- `--dry-run`不产生任何文件。
- 中途失败不留下半生成目录。

### 14.2 Lint

- 覆盖Schema、目录、摘要、危险资源、镜像、资源限制和教学内容规则。
- 覆盖12个现有变体的继承和盲练契约。
- 覆盖3个综合实验的双根因约束。
- 对恶意HTML、Secret、Bearer token、私钥、Manifest和堆栈稳定脱敏。
- 对现有21个实验族零误报。

### 14.3 Fake测试

- 所有现有33场景均可通过统一作者测试入口。
- 普通实验、变体和综合实验生命周期断言完整。
- reset结果与初始故障摘要一致。
- 缺失Fake状态、验证器未知或标准修复不完整时给出精确错误。

### 14.4 Inspect与Package

- 通过前/后公开内容预览准确。
- 修复差异只显示白名单化路径和值摘要。
- 同一输入重复打包的SHA-256一致。
- 包含完整实验内容、索引和摘要，不包含本地垃圾文件。
- 路径穿越、符号链接、超大文件和恶意归档名被拒绝。

### 14.5 工程验收

- Windows负责静态、Fake和构建验证；WSL负责相同检查及可选本机minikube验收。
- pytest覆盖率不低于90%，并通过Ruff、format check、strict mypy、JavaScript语法检查和`git diff --check`。
- wheel/sdist安装后五个作者命令可用。
- 默认测试不启用真实集成变量，不运行真实start/reset/cleanup。

## 15. 指标

### 15.1 核心指标

- 从`lab init`到首次lint通过的中位耗时；
- 首次贡献通过Fake契约测试的比例；
- lint在代码评审前发现的问题数量；
- 现有合法实验的lint误报率；
- 确定性包构建成功率。

### 15.2 质量指标

- 作者工具与运行时Schema规则差异数必须为0；
- 33个现有场景统一契约测试通过率100%；
- 高风险公开内容泄漏漏检数为0；
- 集成验收后的归属资源残留数为0。

M8不上传作者使用遥测。

## 16. 分阶段交付

### M8.0 作者契约与模板

- 固化三类模板、错误模型、CLI参数和安全约束。
- 用现有实验验证模板字段能够覆盖真实需求。

### M8.1 Init与Lint

- 实现安全脚手架、Schema/目录校验和教学契约校验。
- 建立稳定错误码与JSON输出。

### M8.2 Fake契约运行器

- 统一普通实验、变体和综合实验的生命周期测试。
- 将现有33场景接入同一入口作为回归基线。

### M8.3 Inspect与泄漏审计

- 增加公开内容预览、修复差异和敏感信息检查。
- 确保与Web/Application Service DTO边界一致。

### M8.5 本机集成验收与文档

## 17. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 作者工具复制运行时解析逻辑 | 两套规则漂移 | 强制复用Schema、Registry和安全校验服务 |
| 模板生成不安全资源 | 新实验扩大权限 | 固定受限模板并在lint/package双重校验 |
| Fake测试过于理想化 | 实际集群行为不同 | 保留显式本机minikube验收，发布前对内置内容批量运行 |
| Inspect泄漏标准答案 | 破坏盲练 | 区分作者输出与学习者公开预览，默认预览严格执行揭示规则 |
| 自动覆盖作者文件 | 数据丢失 | 非空目标失败、原子写入、首版不提供隐式覆盖 |
| 包成为未审计代码执行载体 | 供应链风险 | 包只允许声明式内容，不执行脚本、不提供自动安装 |
| 集成测试误连其他集群 | 破坏用户资源 | 限制本机minikube、Context Trust、身份摘要和归属校验 |
| 确定性构建受平台元数据影响 | 摘要不一致 | 固定顺序、时间戳、权限、路径和换行规范 |

## 18. 发布门槛

M8进入发布候选前必须满足：

1. baseline、variant、composite三类脚手架均能生成合法内容。
2. 现有21个实验族、12个变体和33个场景通过统一lint与Fake契约测试。
3. 作者工具与运行时Schema、安全规则之间不存在重复实现或行为差异。
4. 恶意路径、危险Manifest和敏感内容测试全部失败关闭。
5. 同一实验包在Windows与WSL生成相同内容摘要。
6. 可选本机minikube验收不自动信任Context，结束后无归属资源残留。
7. 五个作者命令、文档、错误码和JSON输出完成兼容性测试。
